## 2. 見つかった構造的な穴

### A. `public/_headers` の `/spots/*` がスポットの HTML にも効いている（本番で確認）

```
/spots/naha-airport-kids/   Cache-Control: public, max-age=2592000   CF-Cache-Status: HIT
/spots/                     Cache-Control: public, max-age=2592000   CF-Cache-Status: HIT
/spots/city/naha/           Cache-Control: public, max-age=2592000   CF-Cache-Status: HIT
```

画像（`public/spots/*.webp`）向けのルールが、同じパス配下のスポット詳細・一覧・市町村ページにも
30日キャッシュを付けている。デプロイ後の修正（メタ文言・設備の訂正・新規スポット）が、
再訪者のブラウザと Cloudflare エッジで最長30日古いまま出る。
`curl` は毎回取りに行くので、これまでの「本番反映を確認」では見えなかった。

修正案: `/spots/*` を `/spots/*.webp` と `/spots/card/*.webp` に分ける。

### B. 誤り報告の導線が存在しない

`src/components/spot-collection.tsx` の「情報に誤りを見つけられた場合はお知らせください」のリンクは
**同じページへの自己リンク**。連絡先は `/about/` の `mailto` だが、`/about/` へのリンクはフッターにしかなく、
フッターは `hidden md:block` でモバイルでは表示されない。クリックの92%がモバイルなので、
実質ほぼ全員に連絡手段がない。設備情報の正確さを売りにするサイトとして、訂正が届く経路は必要。

### C. 共有手段がない

`navigator.share` / LINE 送信 / X 投稿のいずれもなし。「今日どこ？」の結果も URL に反映されないので
家族に送れない。子連れの行き先決めは配偶者・ママ友と共有して決まるはずで（推測）、
モバイル 92% の環境で共有ボタンがないのは機会損失。

### D. スポット以外のページがゼロ

記事・ガイド・季節・シーン別ページは一切なく、ページ本文は `description` 1段落。
競合調査では、上位常連（いこーよ 1,105件 / あんまーる 500記事 / アソビュー / るるぶKids / Laifue / 沖縄あそびば！）が
「雨の日」「台風」「年齢別」「月別」「モデルコース」「座敷・個室ランチ」を記事化している。

一方で **設備フラグを持つ DB で答えているサイトは競合にない**。たとえば `typhoonOk` を持つのはこのサイトだけ。

### E. 年齢ページが索引されない

トップの「年齢で選ぶ」4カードは `/spots?age=...`（クエリ版、canonical は `/spots/`）へのリンク。
年齢軸は競合（いこーよ・るるぶKids・JTB）が持っていて需要がある軸なのに、このサイトでは Google から見えない。

### F. 更新日・確認日の表示がない

`dateModified` は JSON-LD になく、画面にも「最終確認日」がない（Q&A の脚注に一部あるのみ）。
設備情報は変わるので、「いつ確認した情報か」が見えないと信頼されにくい（推測）。

### G. 細かい点

- README は「PWA対応（オフライン基本対応）」と書いているが Service Worker はない。manifest はある。
- FAQ の JSON-LD はないが、Google は2023年以降 FAQ リッチリザルトを行政・医療サイトに限定しているので**追加不要**。
- Yahoo からの流入 30/170 は Google のインデックスを使っているので個別対策は不要。

## 5. 計測基盤について

GSC が主計器。Cloudflare Web Analytics は10刻みの丸めでイベントが取れないので、
「共有ボタンが押されたか」「フィルタが使われたか」は今の構成では測れない。
計測を足すなら、先に §4 の内容を入れてから必要になった時点で最小限にする。
